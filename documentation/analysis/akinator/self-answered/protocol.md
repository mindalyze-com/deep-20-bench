# Self-answered Akinator protocol

The user renewed this comparison after stopping the paid Oracle experiment. They requested Codex to answer, allowed Probably and Probably not, and reduced the scope to a single round over the subjects. This arm contains exactly one game attempt for each of the ten active subjects, in catalog order. An attempt ending in a website error is not repeated.

The English Akinator web interface was operated through the browser. Characters was used for the five people or characters; Objects for the five things. Each attempt began from Home, Play and theme selection. The target catalog is the [same frozen catalog](../oracle/subject-catalog.json) as the Oracle arm. Stephen King and Mario were inactive.

Codex answered from its knowledge and occasional factual lookups. Lookup URLs and short interpretation notes are retained in the records. Unknown was available when facts or the intended referent could not be established. No Oracle, Reviewer, Judge, paid Guess Validator or OpenRouter call was made. This is an informal operator-answered comparison; it does not inherit the production pipeline's independent answer checks.

| Recorded token | Website button |
| --- | --- |
| YES | Yes |
| NO | No |
| UNKNOWN | Don't know |
| RATHER_YES | Probably |
| RATHER_NO | Probably not |

Answers generally use ordinary game meanings and typical uses. Broad object categories remain broad: for example, the bike-pump target includes manual and electric designs. Personal questions with unspecified preferences receive Unknown. Generic human-use questions are interpreted as ordinary human use. Character origins are distinguished from portrayals, while questions about whether a portrayal has ever appeared or died can refer to those portrayals. These are operator judgments, not a mechanically enforced or independently reviewed semantic policy.

Only the answer buttons and correctness confirmations were entered into Akinator. Subject names, catalog descriptions, private evidence, notes and other component records were not supplied to the site. Failed games were not trained by entering the target name. Correct guesses did receive the site's normal confirmation feedback.

## Stopping and scores

Success is exact identification of the catalog target or an equivalent name. The operator judges displayed guesses. A broader class is recorded as a near miss rather than an exact success. For Bike pump, "An air pump" was rejected because it did not identify a bicycle pump; its image showed a general electric inflator. This judgment is explicit in the raw record and can be audited.

Record success within 20 answered factual questions and within 40 counted actions. ASK answers and rejected guesses each count one action; a correct terminal guess and the Continue button do not. At the limit, only an already displayed final guess may be evaluated. No extra factual answer is submitted to obtain another guess.

The browser advancing to the next question or result verifies a submission. Schweitzer's Q19 click led to a technical error, so only Q1-Q18 are confirmed and the acceptance of Q19 is unknown. That attempt is excluded from score and question averages. Coverage is also reported over all ten starts so the excluded attempt stays visible.

There is no answer caching or paid prompt caching in this arm. No new scheduled run, replay suite or automated benchmark was added. Timestamps include UI delays, source lookups, pauses and documentation work and should not be used as a model-speed comparison.

## Retention

The user explicitly requested public repository retention of both arms, including raw questions and answers, Markdown summaries, and one or two successful screenshots as WebP. The two screenshots are actual browser captures, converted in memory to lossless WebP. Achilles shows the confirmed success page. Genghis Khan shows the exact guess immediately before its subsequently verified Yes confirmation. No page contents were changed for the captures. The page's narrow layout, overlays and advertisements are retained.

These files are analysis artifacts. They do not change benchmark inputs, prompts, production behavior or the generated publication site.
