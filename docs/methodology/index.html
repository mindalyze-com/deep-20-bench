Methodology

How the benchmark works.

A model identifies a hidden subject by asking yes-or-no questions. The publisher scores completed runs. It does not rerun or change them.

01 · Protocol02 · Scoring03 · Reliability04 · Eligibility05 · Isolation

01 · Protocol

Core subjects · protocol v9

Question, answer, guess.

The Guesser receives a broad category. It asks questions and receives YES, NO, or UNKNOWN.

Question limit50
Subjects7
Trials / subject5
Base seed0

The Validator checks the final guess. The Guesser never sees the subject, evidence, provider data, or hidden state.

If the Guesser breaks the structured-output contract before the limit, the attempt is not judged. It loses one counted turn, receives one fixed format reminder that gives no right-or-wrong feedback, and may try again.

02 · Scoring

b20-linear-v1

B20 uses 20 as the target.

Higher is better. A B20 Score of 20 means 20 penalized questions.

Trial valuesuccess: questions · failure: 51
B20 transformation20 × (51 − P) ÷ 31
Reference points20 questions → 20 · failure → 0

A successful trial uses its counted questions. A model failure gets 51, one above the limit. Trials are averaged by subject first, so each subject has equal weight. Ranking uses the exact penalized-question value. B20 shows the same order on a higher-is-better scale.

Raw questions are also shown

Run, subject, and episode pages show counted and penalized questions. Infrastructure failures are not scored. B20 is not a percentage.

03 · Reliability

Independent aspect

Success does not erase a broken contract.

Every invalid structured response remains visible, even when the model later finds the subject.

Turn consequencepre-limit violation → one counted turn
Semantic feedbacknone · format only
Published measurevalid outputs ÷ evaluated outputs

Episode, subject, run, and leaderboard pages show compliance, violations, affected trials, and counted-turn penalties. These turns already affect the question total, so reliability does not add a second B20 penalty.

04 · Eligibility

Official selection

Rules for official results.

Completed benchmark evidence is the qualification rule.

  • Run files pass integrity checks.
  • The run is terminal and contains every active subject.
  • Every subject has all five completed trials, numbered 1 through 5.
  • Completed model failures remain valid scored trials.
  • A missing or infrastructure-failed trial waits for its retry.

The publisher accepts only the current signed artifact schemas and protocol. If several current runs qualify for one model, only the newest completed run is published; the best score is not selected. Non-qualifying runs are omitted from the public projection, and invalid input stops the build.

05 · Isolation

Information boundary

The publisher reads completed runs.

Model calls→Signed artifacts→Public projection→Static site

The publisher is a separate package. It reads completed run files and creates the public dataset. It does not import the game, Oracle, provider, prompts, credentials, sessions, or retry code.

Published data never returns to the Guesser. The build needs no API key and makes no model calls.
