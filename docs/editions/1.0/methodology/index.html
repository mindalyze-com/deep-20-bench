Method · Edition 1

How Deep20Bench works

Deep20Bench tests how well AI models find a hidden subject by asking questions. Models play the same subjects repeatedly. Fewer questions and fewer failed rounds give a better score.

01 · The game02 · Answer checks03 · The score04 · Comparisons05 · Explore results

01 · The game

Find a hidden subject.

A subject is the person, character, or thing to identify. The model being tested, called the Guesser, starts with only a broad category. It asks one question at a time, uses the answers to narrow the possibilities, and makes a guess.

This round scores three questions. The correct guess does not count. A wrong guess counts as one question and play continues. For example, 12 questions, one wrong guess, and one reply in the wrong format before the correct guess score 14. The limit is 50 counted questions, followed by one final guess.

Guess rules and the question limitDetails +Close −

Not finding something in a search is not enough for No. Guesses get only Yes, No, or Unknown. Only Yes ends a round successfully.

A guess must identify the exact subject; accepted alternative names count.

The limit is higher than twenty so that a model that needs, say, 25 questions scores better than one that never finds the subject. Every extra question still raises the score. At the limit, the model can only guess. If that guess is wrong, the round scores 51, one more than any successful round.

02 · Answer checks

How answers are checked.

Other models know the hidden subject and answer the Guesser’s questions. Up to three roles are involved, each with a separate job:

  1. Oracle: find an answer.

    Searches for evidence and proposes an answer. Unknown is final; every other answer needs a second check.

  2. Reviewer: check independently.

    Checks the question without seeing the Oracle’s answer. If they agree, that answer is final.

  3. Judge: resolve disagreement.

    Decides whenever their answers differ, including Reviewer Unknown. It sees neither earlier answer.

Guesses go to a separate Guess Validator, which checks whether the guess names the subject. The Guesser receives only the final answer, with no explanation.

The Guesser cannot see the answer checks.

It sees the category, its own questions and guesses, and the final answers. The hidden subject, searches, evidence, and other models’ conversations stay private.

If the same question was already checked, its answer can be reused. The transcript marks reused answers.

What the checking models can seeDetails +Close −

The Oracle receives the subject and the current question, but no earlier turns. For a new answer, it searches the web and keeps the source text. It must search instead of relying on memory.

The Reviewer and Judge receive the subject, the question, and the Oracle’s numbered evidence. They cannot search the web or see earlier answers or the game history. If a required check fails, the round counts as a test system failure; the Oracle’s answer is never used on its own.

For narrow, settled facts, the Reviewer and Judge may use their own knowledge when the evidence is not enough.

The Guess Validator receives only the subject and the guess, with no web access. The Guesser never sees sources, other models’ instructions, checking decisions, logs, or private files. Its own instructions and format reminder contain nothing about the subject.

Early runs exposed basic Oracle errors: one answer said Yes to “born before 1800?” while citing 1875. The Reviewer and Judge use different model families and providers to reduce shared mistakes.

When an earlier answer is reusedDetails +Close −

New benchmark runs reuse answers by default. A question that matches an earlier one can reuse its fully checked answer, either from an earlier compatible round or from the same game. Standalone games always check anew. The run’s recorded rules decide which answers qualify.

Reused answers keep their original evidence, time, and source label in the transcript. They are not new web checks. The question still counts, but adds no answer-checking calls or cost. The Guesser sees only the final answer. Compare runs only if they use the same reuse rules and answer history.

03 · The score

Fewer questions means a better score.

Average the round scores for each subject, then average those subject scores. Every subject has equal weight. This is the model’s question score.

Each score has a 95% confidence interval: an estimate of uncertainty in the average from repeated rounds on these subjects. A narrower interval means more consistent results, even if the score itself is poor. It does not describe performance on new subjects.

The Stability view ranks models by this interval’s width. Cost and time are reported separately and do not change the question score.

Format errors and failed roundsDetails +Close −

Each Guesser reply must be one valid ASK or GUESS action. Before the question limit, an invalid reply uses one counted turn and gets a fixed FORMAT_ERROR reminder. The reminder says nothing about what went wrong, whether the model was right, or the subject. Too many invalid replies in a row end the round as a scored failure. An invalid final guess ends the round with no retry and no extra counted turn.

A later correct guess does not erase earlier format errors. Round, subject, run, and leaderboard pages show the share of valid replies, the number of errors, the affected rounds, and the turns used. The used turn is already in the question score; there is no second penalty.

How the interval is calculated

Estimate the variation between rounds separately for each subject, divide by that subject’s round count, then combine the estimates with equal subject weights. A Welch-Satterthwaite t interval allows different variation for each subject.

Standard errorSE=1S∑s=1Sσˆs2nsS = subjects · ns = rounds for subject s · σ̂2s = sample variance of round scores for subject s
95% intervalmodel score ± t critical value × standard error

The interval describes uncertainty in the average, not the range of single rounds. It does not cover other subjects, changes to models or providers, or future editions. It assumes that rounds on the same subject are independent; different seeds support this but do not prove it. Comparing two models’ intervals is not a significance test.

Reused answers can link rounds. The interval does not adjust for this or estimate how new web research might change answers. Stability ranks use the interval width at the same 95% level for every model.

04 · Comparisons

Repeat the game on the same subjects.

In this edition, each model plays 7 subjects 5 times each: 35 rounds in total. Every round starts a fresh Guesser conversation. Repetition shows how much results vary.

Only complete runs with accepted settings enter the leaderboard. If several runs qualify for a model, it uses the newest completed run, never the best score.

What a comparison can tell you

These results describe a small, fixed set of subjects. They do not rank general intelligence or predict performance on unseen subjects. Repetition does not make the subjects more representative. Public subjects and transcripts may also have appeared in a later model’s training data; we cannot rule out an advantage from this.

Subjects, repeated rounds, and future editionsDetails +Close −

Each subject has a main name, accepted alternative names, a clear description, and a public reference. Every model in an edition uses the same list, shown with categories in each run. The selection is not random, balanced, or representative. Cost limits its size: each added subject needs repeated model turns and answer checks.

A round cannot see another round’s transcript, evidence, or private data. Each round starts with a code made from the base seed and the round number. It is the same for every model and subject and reveals nothing about the subject. Base seed: 0.

Future editions should include more subjects and kinds, such as places and objects. Subjects and selection rules will be fixed before testing. Any change to subjects or game rules gets a new edition with separate results.

Requirements for a published runDetails +Close −

Only the Guesser changes between runs. The subjects, game rules, Oracle, Reviewer, Judge, Guess Validator, round count, and scoring rules stay the same.

  • Signed run files must pass integrity checks.
  • The run must be finished, with every round of every subject complete.
  • Rounds the model failed count as scored. A run with missing rounds or test system failures stays out until those rounds are rerun.

Any invalid run file stops the site build.

Cost comparisons use the final attempt of each round. Earlier attempts that were rerun after a test system failure stay in the records and the total spend, but not in the cost comparison.

05 · Explore results

Follow a score back to the game.

Open a model’s run to see its subjects and rounds. Each round shows the questions, answers, guesses, and supporting evidence, along with format errors, usage, cost, and timing.

Answers are checked by models, not independently verified. The transcripts let you check the evidence and spot mistakes.

How results reach this websiteDetails +Close −

Publication happens after play is finished. The site is built from saved, verified result files. It never takes part in a game, and published data never returns to the Guesser.

The publishing code is a separate package that cannot call models. Public data excludes private prompts, hidden reasoning, provider logs, and credentials.

Benchmark editions

What changed in 1.1

Version 1.0 answers questions with Yes, No, or Unknown. Version 1.1 adds Rather yes and Rather no, so an answer can lean one way when the evidence is incomplete.

Why add Rather yes and Rather no?

Web evidence often points one way without fully proving the claim. With only three answers, Unknown throws that hint away, while a firm Yes or No can claim more than the evidence shows. The two new answers keep the hint and mark it as uncertain.

Whether this improves the game still needs testing. More answer options alone do not prove better accuracy.

Edition 1.1 also revises the Guesser's strategy instructions and adds a fixed guide to what each category means. Scores, uncertainty, costs, and efficiency are calculated separately for each edition, with the same formula and equal subject weights. Because the subjects, round counts, limits, and prompts also differ, a score difference between editions cannot show the effect of the new answers or that a model improved.
